# 四阶段执行契约

主进程持久化运行、阶段尝试、问题和成果；Skill 仅负责分析与写作指导。输入版本由宿主冻结，模型不得以自然语言宣布状态转换或维护另一套任务状态文件。

| 阶段 | 输入 | 输出 | 宿主验收重点 |
|---|---|---|---|
| requirements | 招标正文、有效补疑、适用附件 | 有效要求、条款修改关系、出处、冲突问题 | 关键资料解析完整，关键要求有证据，阻断冲突已解决 |
| boq | 招标清单、清单说明、范围约束 | 清单项、主要施工分组、数量汇总、异常项 | 来源可定位，数量单位特征不变，费用项明确处理，无重复统计 |
| draft | 已发布要求及清单、确认结果、必要图纸和知识 | 目录、统一计划、结构化章节、附表、两类覆盖关系 | 必需要求和适用分项覆盖，数字与来源一致，无未处理阻断问题 |
| deliver | 已验收章节、计划、模板及格式规则 | DOCX、可选 PDF、实际检查报告、成果 ID | 文件存在可解析，格式和内容检查通过，成果登记成功 |

## 资料与确认

PDF 保留物理页及可核实印刷页；Excel 保留工作表、源行和单元格；DOCX 保留逻辑块。无法解析 DOC/XLS、DWG 或专有文件时使用可核实的转换结果或请求导出文件，不声称已读取。

要求和清单在分类前保留原文。用户确认单独记录，不改写源文件。非阻断问题可在草稿中披露，正式交付不隐藏未确认内容。

## 执行边界

仅使用宿主提供的阶段工具。清点、计划计算、Word 构建和转换不以任意 Shell 命令调用。缺少解析器、计算器、模板或转换依赖时明确报告受阻。

计划先经确定性计算，再被章节和图表统一引用。模型不能自行填关键路径或用无来源产能作正式承诺。标准和工法按项目需要查询，不自动认定内置卡已获专业批准。

## 恢复与交付

阶段尝试由宿主经历 pending、running、validating、succeeded，失败、取消、中断及等待确认均由宿主登记。重试建立新尝试，输入变化使受影响阶段及下游失效。不得通过保存 completed 标记绕过验收。

要求到章节、清单分组到章节分别建立对应关系。文档必须检查实际输出，不以模型自填的通过报告代替检查。只返回宿主登记的成果 ID，不将任意本地路径当下载入口。
