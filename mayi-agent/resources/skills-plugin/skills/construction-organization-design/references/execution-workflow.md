# 施组编制八阶段执行工作流

本文件定义施组编制的阶段门、子流程、文件操作和结构化产物。所有阶段在 `.mayi/tasks/$MAYI_SESSION_ID/construction-plan/` 下执行，不修改用户原文件。

## 通用状态与阶段门

`task-state.json` 至少记录：输入文件指纹、当前阶段、各阶段状态、产物路径、阻断问题、最近成功时间。阶段状态只能是 `pending`、`in_progress`、`blocked`、`completed`、`stale`。

- 输入新增、删除或内容变化时，将受影响阶段及其下游标记为 `stale`，只重跑受影响部分。
- 每项结论使用 `confirmed`、`conflicting`、`not_found`、`pending_confirmation` 四种事实状态。
- 存疑项分为阻断项和非阻断项。阻断项未确认不得进入依赖该事实的定稿；非阻断项可使用明确标注的假设继续形成草案。
- 向用户提问时按阶段集中列出，说明冲突证据、影响范围和建议选项，不零散追问同一类问题。
- 更新阶段状态前验证 JSON 可解析、必填字段存在、引用文件可定位；正文、表格和附图不能成为独立事实源。

## 00 资料分类整理与可读性检查

### 子流程

1. 递归清点文件，按招标及补疑、图纸及设计说明、清单及控制价、地勘测量及管线、合同及管理制度、投标人资料、现场踏勘、参考资料分类。
2. 计算相对路径、扩展名、大小、修改时间和内容哈希，识别重复文件、同名不同版、压缩包、空文件和损坏文件。
3. 判断文本型、扫描型、表格型、图纸型和专有格式，记录可读性及所需工具。
4. 建立版本链和初步来源优先级；补疑编号不连续、存在“最终版/修改版”但无变更说明时标记待确认。
5. 输出资料完整性结论，只说明是否可以进入招标分析，不提前撰写正文。

### 文件操作

- PDF：逐页提取文本并保留页码；文本过少时渲染 OCR；表格、图章、流程图和总平面图必须结合页面图像复核。
- DOC/DOCX：提取正文、表格、页眉页脚、批注和修订；旧版 DOC 无法可靠读取时先转换副本，不覆盖原件。
- XLS/XLSX：记录工作表、有效区域、隐藏表、合并单元格、公式、单位和打印区域；同时读取公式与缓存值，不把空白格式区域当工程数据。
- DWG：优先以同版本签章 PDF 作为事实证据，DWG 用于尺寸和图层辅助核对；无法解析时必须标记未验证。
- HFZF、ZB 等专有格式：只有成功解析并能定位字段时才引用；否则要求用户导出 PDF、清单或评标办法，不声称已读取。
- 图片：保留原图与 OCR 结果；尺寸、标高、工程量等关键数字必须人工视觉复核。
- 压缩包：解压到阶段临时目录，检查路径穿越和重复层级，不执行其中程序、宏或脚本。

- `00-intake/file-inventory.json`
- `00-intake/source-register.json`
- `00-intake/unreadable-files.json`
- `00-intake/completeness-report.json`

G0 通过条件：招标主文件、现有补疑变更、主要图纸或设计说明、清单范围均已登记；不可读和缺失文件已明确告知用户。

## 01 提取招标红线和评分要求

### 子流程

1. 识别最新招标正文、投标人须知、评标办法、技术标准、合同专用条款、补疑和变更公告。
2. 分别提取否决项、资格条件、符合性要求、评分项、合同履约要求、格式要求和建议性表述。
3. 提取工期、质量、安全、文明施工、实名制、扬尘、智慧工地、危大工程、人员设备和专项承诺要求。
4. 提取暗标规则，包括字体、字号、页数、颜色、页眉页脚、文件属性、图片标识和附件命名。
5. 将每个评分项拆为可验证的响应单元，映射计划章节、附表附图和验收证据。
6. 合并补疑和变更；只按明示规则覆盖，不推测隐藏权重或评委偏好。

### 文件操作

- 所有规则必须保存文件名、页码或章节、原文摘要和版本日期。
- 表格跨页时合并表头并核对分值合计；扫描文字中的数字、否定词和日期必须视觉复核。
- “应、须、不得、否决、无效”与“宜、建议、参考”不得混为同一级别。
- 补疑编号缺失、条文互相覆盖或评分总分不一致时写入冲突台账，不自行选择。

### 产物与阶段门 G1

- `01-tender/requirement-traceability.json`
- `01-tender/format-and-anonymous-rules.json`

G1 通过条件：否决项和格式红线全部有证据；评分项已拆解；阻断性招标冲突已集中向用户确认。

## 02 建立项目事实库

### 子流程

1. 从招标文件确定项目名称、标段、地点、范围、工期和目标。
2. 从签章图纸及设计说明提取道路、排水、管综、交通、照明、绿化等专业事实。
3. 从清单和控制价提取专业构成、主要工程量、材料规格、措施项目和暂列内容。
4. 从地勘、测量和管线资料提取地层、地下水、软弱地基、既有管线及周边约束。
5. 从现场踏勘和投标人资料提取临建、交通、临水临电、人员、设备、供应和组织条件。
6. 每个关键事实绑定证据、权威等级、状态和置信度；计算值保存公式、输入和单位。
7. 调用 `construction-standard-registry`，按项目地区、专业和适用日期查询招标、设计、图纸和清单明确引用的标准，区分已核验、过期缓存、待审核和未命中记录。

### 文件操作

- 图纸目录、图号、版次和签章状态先于图纸内容登记；同一专业存在多个版本时只将最高优先级版本作为当前值。
- 清单按专业、分部、项目编码、名称、特征、单位和数量读取；不得只根据控制价反推施工数量。
- 设计图与清单数量不一致时并列保存，不擅自修改清单或设计值。
- 地勘和管线成果必须记录勘察日期、适用范围和限制条件；历史探测资料不得描述为施工前复核结果。
- 参考施组、评估报告和行业经验只能标记为参考，不能进入已确认项目事实。

## 03 跨文件冲突检查与存疑确认

### 子流程

1. 比对招标正文、补疑、图纸、清单、地勘、管线和现场资料中的名称、范围、日期、数量和参数。
2. 调用 `document-comparison` 对齐招标正文、补疑、清单及不同版本文件，输出新增、删除、修改、位置移动和无法可靠对齐的内容。
3. 检查道路长度及结构、管径及材质、标高及埋深、土方及处置、专业界面和暂估内容。
4. 检查工期、里程碑、质量安全目标、人员设备最低配置、格式及暗标规则。
5. 将冲突分为阻断、高、中、低，评估影响的章节、图表和计划。
6. 形成集中确认单。用户确认后记录确认内容、时间和适用范围；未确认项不得伪装成事实。

### 文件操作

- 冲突条目必须同时保存各版本证据，不删除被覆盖值。
- 用户口头确认作为单独来源记录，不能改写原文件证据。
- 阻断项包括可能导致否决、范围错误、工期不可计算、主要工法错误或暗标违规的问题。
- 非阻断项允许使用占位符或方案假设，但必须进入最终未决事项检查。

### 产物与阶段门 G3

- `03-conflicts/conflict-register.json`
- `03-conflicts/confirmation-questions.json`
- `03-conflicts/confirmation-decisions.json`

G3 通过条件：阻断冲突已关闭，或用户明确同意在指定假设下继续编制草案。

## 04 形成施工策划

### 子流程

1. 根据工程实体、场地条件和工期建立施工分区、施工段和 WBS。
2. 确定总体顺序、专业穿插、工作面移交、关键线路、里程碑和验收节点。
3. 制定交通导改、地下管线保护、土方平衡、临排水、临水临电和总平面方案。
4. 对重点难点和危大工程建立“条件—风险—措施—责任—指标—检查—异常处置—验收证据”闭环。
5. 根据工程量和工期计算劳动力、机械、材料和供应计划，校核峰值及场地承载能力。
6. 将每个评分响应单元映射到策划措施、正文章节和附表附图。
7. 调用 `construction-schedule-planning` 校验 WBS 有向无环关系，计算 CPM 日期、总时差、自由时差、关键线路、计算工期和资源峰值。
8. 调用 `municipal-construction-methods`，根据项目事实标识筛选工法卡；缺少必要事实时写入存疑确认，选定版本后生成项目工法快照。

### 文件操作

- `construction-plan.json` 是工期、WBS、资源和图表的唯一策划数据源。
- 关键线路、时差和资源峰值必须来自 `construction-schedule-planning` 的确定性计算结果，不得由模型直接填写。
- 横道图、网络图、劳动力曲线、机械计划不得分别手填独立数字。
- 所有推算记录依据、公式、假设和敏感性；没有现场条件时不得确定具体临建坐标或运输路线。
- 策划结论与事实库冲突时返回阶段 02/03 修正，不在策划文件中覆盖事实。

## 05 编制高分施组正文

### 子流程

1. 按招标目录和评分映射生成章节骨架，不用固定模板覆盖项目要求。
2. 先写项目概况、重难点和总体部署，再写进度、资源及各专业工法。
3. 编写质量、安全、文明施工、环保、季节性施工、应急、信息和资料管理。
4. 每个评分项使用明确标题，包含项目依据、施工动作、量化控制、责任岗位、检查记录和验收标准。
5. 对未决事项使用统一占位符并链接确认问题，禁止生成看似确定的虚构内容。
6. 完成章节级自检后合并全文，生成评分响应索引。

### 文件操作

- 分章节保存到 `05-draft/chapters/`，每章记录依赖的事实 ID、评分项 ID 和策划项 ID。
- 引用规范前核对名称、编号、版本和适用范围；无法核实时避免写具体编号。
- 禁止复制其他项目名称、地点、人员、设备、塔吊或施工电梯等无关模板内容。
- 修改权威事实时先改结构化源并重生成受影响章节，不在 DOCX 中局部修补。

### 产物与阶段门 G5

- `05-draft/full-draft.docx`
- `05-draft/scoring-response-index.json`
- `05-draft/open-placeholders.json`

G5 通过条件：正文覆盖全部强制要求和评分项；不存在无来源的关键数字；所有占位符均已登记。

## 06 制作附表和附图

### 子流程

1. 从策划数据生成横道图、网络计划、里程碑、劳动力和机械材料计划。
2. 基于已确认场地资料绘制施工总平面、临建、交通导改、临排水、临水临电和消防布置。
3. 制作施工流程、质量控制、安全管理、管线保护和应急响应图。
4. 建立图表编号、正文引用和评分项映射。
5. 对无法按比例或缺少坐标的示意图明确标注“示意”，不得伪装为施工放样图。

### 文件操作

- 表格计算底稿保存在 `06-appendices/tables/`，公式必须可复算且无公式错误。
- 图件源数据保存在 `06-appendices/figures/`；导出后检查文字、比例、图例、方向和打印清晰度。
- 图表中的工期、数量、人员和机械必须从阶段 04 生成。
- 签章设计图不得擅自修改后作为施工组织设计附图；需要引用时标注来源和用途。

### 产物与阶段门 G6

- `06-appendices/appendix-register.json`
- 进度、资源、平面和流程图源文件及导出文件

G6 通过条件：正文引用均能定位，图表可读，数据与策划一致，暗标内容已清理。

## 07 最终审查与闭环修订

### 子流程

1. 运行否决项、强制项和评分覆盖检查。
2. 运行事实、工期、工程量、资源、图表和正文一致性检查。
3. 检查其他项目残留、虚构承诺、过期规范、危大工程遗漏和不合理工法。
4. 调用 `construction-standard-validation` 校验结构化标准引用，并读取标准状态变化产生的项目复核影响。
5. 检查目录、编号、交叉引用、页眉页脚、文件属性、图片水印和暗标风险。
6. 转换 PDF 并逐页检查分页、表格截断、图片清晰度、空白页和字体替换。
7. 按阻断、高、中、低建立问题台账，修改后重跑受影响检查，直至关闭或明确接受风险。

### 文件操作

- 审查不得只搜索正文文本；必须检查 DOCX 结构和 PDF 实际渲染结果。
- 修订记录保存问题位置、依据、修改动作和复核结果。
- 未关闭的阻断或高风险问题存在时不得标记正式交付。

## 08 定稿交付

### 子流程

1. 按招标要求生成 DOCX、PDF 和必要的 XLSX、附图文件。
2. 核对文件名、格式、页数、大小、目录、书签、可打印性和附件清单。
3. 生成交付清单、事实版本、未决事项和检查结果摘要。
4. 保留可编辑源文件和结构化数据，确保后续补疑或事实变化可增量重生成。

### 文件操作

- 正式交付文件写入 `08-delivery/`，不得覆盖用户原始招标资料。
- DOCX 与 PDF 的正文、页数和图表版本必须对应；转换后重新执行暗标和视觉检查。
- 若用户只要求草案，应明确标注草案状态和未确认事项，不使用“最终版”“已通过审查”等表述。

### 产物与阶段门 G8

- 正式 DOCX/PDF/XLSX/附图
- `08-delivery/delivery-manifest.json`
- `08-delivery/unresolved-items.json`
- `08-delivery/final-readiness.json`

最终状态只能是 `ready`、`draft_with_confirmations` 或 `blocked`，不得宣称获得官方评分、通过青天审核或保证中标。
